# Validation scope

Validated environments: Python 3.12 with PyTorch 2.14.1+cpu and a clean
installation with PyTorch 2.15.0+cpu. No usable CUDA GPU or
licensed Human3.6M recordings are present in this environment.

Run from the repository root after installation:

```bash
python -m pip check
python -m pytest -q
```

Tests under `tests/system/` create a temporary 99-column, 50 Hz text export
with the real subject/action layout. It has eight varying body features that
do **not** form rotation triplets; this makes invalid reduced-vector reshaping
detectable. They exercise the production loader, model, losses, trainer,
checkpoint restorer and evaluator, not dummy versions.

Coverage:

- All six training variants perform actual predictor updates; every active
  discriminator also changes its weights with finite gradients.
- Train-only normalization, S5 leakage rejection, explicit root exclusion,
  action labels, complete joint restoration and epoch-varying windows.
- Correct zero-angle rotation derivative, known angular distances, finite
  gradients, raw-target retention and root-independent Euler evaluation.
- Exact CPU model and optimizer equality after resume versus uninterrupted
  training. Different objective settings are rejected on resume.
- Both 10-frame and 25-frame training, with evaluation rollout to 100 frames.
- Default 1024-hidden predictor and both default-size critics execute together.
- Real subprocess invocations of `python -m aged.train`, resumed training and
  `python -m aged.evaluate`, including persisted JSON results.
- Conditional full CUDA training/evaluation test; skipped on this machine.

The whole-pipeline suite completed with **13 passed, 1 CUDA skipped**, including
the clean CPU environment prepared with `bash scripts/setup.sh --cpu`. In the environment
with optional TensorBoard installed, the actual CLI train/resume/evaluate test
also passed and verified that event files were written. Both installed console
entry points were checked from outside the repository. Synthetic scores are
deliberately not listed as Human3.6M benchmark numbers.

The installer now defaults to CUDA mode for formal GPU training. CPU mode,
invalid option rejection and rejection of an existing CPU wheel in CUDA mode
without a CUDA installation index were exercised. The official cu128 index was
queried for available wheels, but CUDA wheel installation, driver compatibility
and real GPU execution remain unverified on this CPU-only machine.

Before reporting a reproduction result, run on the authorized real export,
verify zero-velocity against published tables, check action averaging and the
fixed-window/Euler convention, train the requested horizon for 50 epochs, and
evaluate on S5 using checkpoint statistics. Preserve configuration, code commit,
checkpoints and JSON results for every reported experiment.

## Reconciled team features and old-checkpoint compatibility

The reconciled whole-pipeline suite completed with **22 passed, 2 CUDA skipped**
on Python 3.12 / PyTorch 2.15.0+cpu. The earlier 13-pass result above describes
the initial integration, not a GPU experiment.

Additional checks exercise direct/column critics, strict component-weight
imports, derivative signs and extreme logits, D/G gradient isolation, SGD/Adam,
per-critic optimizers, LR schedule resume, warm start with fresh critics,
early stopping, periodic snapshots, uniform recording sampling and CLI aliases.
The synthetic-data published-baseline gate correctly fails and retains its
diagnostic JSON. The second skipped GPU case covers the team's direct critics
with separate optimizers; current hardware cannot execute it.

Before changing production code, an actual `be674c6` checkpoint and a second
epoch continuation were generated by the old code. New-code inference and
continuation matched that old-code reference exactly, including optimizer
tensors, on the same CPU runtime. Automated tests additionally cover v1
checkpoints without newly added fields. Cross-GPU/version bit-exactness is
not implied by this CPU result.

The adapted continuity notebook completed bounded synthetic runs for all four
real/fake scenarios and sampling through the production dataset API. Original
MPS experiment files are preserved unchanged, not claimed as rerun results.
The wandb adapter was exercised through actual training with a local test
client; no external wandb account or remote service connection was tested.

## Team-supplied real-data GPU record (earlier code)

The subsequently supplied `integration-checks.zip` records commit `224b948` on
Windows / RTX 4070 / PyTorch 2.15.0+cu132 with a 210-file real H3.6M export.
Its 22 pipeline steps succeeded, including 14 automated tests and a CUDA case;
four separate optimizer diagnostics also completed. This is an external team
record, not a rerun in the current CPU environment or GPU validation of all
new options in `51d23d1`.

The saved zero-velocity JSON matches all 60 short-term reference entries within
the current 0.0055 tolerance (maximum absolute difference about 0.004891), using
the documented inferred Sitting/160 ms correction; four long-term action rows
also round to the published values. Adam at LR 0.005 trained poorly, while SGD
at that LR was markedly more stable in the controlled diagnostic. The SGD full
model after 2000 steps still slightly exceeded its S11 zero-velocity baseline.
These are integration/diagnostic results, not a reproduction benchmark.

## Local training dashboard

The dashboard uses the production trainer in an isolated subprocess and adds
optional progress/epoch-stop callbacks. CLI behavior and checkpoint format stay
unchanged. The combined CPU suite completed with **25 passed, 2 CUDA skipped**.
New HTTP pipeline checks exercise real updates, saved-epoch stopping, resume,
bit-exact CPU model equality against a normal run, malformed-data traceback,
preflight validation, task exclusion, local request checks, log downloads and
worker termination.

Headless local Chromium checks fill the actual form and paths, browse a
directory, execute training, observe real SVG curves, filter logs, export
configuration, reload the page, resume and display an actual worker failure.
A 390-pixel mobile viewport was checked for horizontal overflow; no browser
JavaScript errors or CSP violations were observed. A wheel build includes all
HTML/CSS/JS assets. These runs use synthetic CPU data; CUDA and native Windows
dashboard execution still require validation on the training machine. See
[local dashboard usage](LOCAL_TRAINING_UI.md).
